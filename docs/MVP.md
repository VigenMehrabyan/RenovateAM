# RenovateAM — MVP

Версия 0.1 · 23.08.2026

---

## 1. Цель MVP

Проверить одну гипотезу: **если клиент получает ориентир по цене до выезда, часть нецелевых по бюджету отсеивается сама, и компания перестаёт тратить выезды и часы сметчика впустую.**

MVP считается успешным, если через 3 месяца после запуска снизились **часы выезда и работы сметчика на одну закрытую сделку**. Рост числа регистраций и заявок успехом не является.

## 2. Границы MVP

Один сквозной сценарий:

```
Лендинг → Быстрый расчёт → Регистрация → Верификация e-mail
   → Загрузка БТИ и дизайна → Заявка → Смета от сметчика → Принято / Отклонено
```

### Входит

| # | Функция |
|---|---|
| F1 | Лендинг с описанием услуги и калькулятором |
| F2 | Быстрый автоматический расчёт без регистрации |
| F3 | Маршрутизация нестандартных пакетов на ручное рассмотрение |
| F4 | Регистрация: ФИО, e-mail, телефон, адрес объекта |
| F5 | Верификация e-mail по ссылке |

| F7 | Личный кабинет: список заявок, статус каждой, полученная смета |
| F8 | Отправка заявки на ручное рассмотрение |
| F9 | Админ-панель: очередь заявок, файлы, загрузка сметы, статусы |
| F10 | Редактор базовой ставки и коэффициентов |
| F11 | Уведомления: e-mail (обязательно), WhatsApp (опционально) |

## 3. Роли

| Роль | Права |
|---|---|
| Гость | Лендинг, быстрый расчёт |
| Клиент | Всё выше + заявка, загрузка файлов, кабинет, решение по смете |
| Сметчик | Очередь заявок, просмотр файлов, загрузка смет, смена статусов |
| Админ | Всё выше + редактор ставок, список пользователей |

В MVP роли сметчика и админа реализуются как одна учётная запись с флагом `role`. Разделение прав — после MVP.

## 4. Пользовательские сценарии и критерии приёмки

### US-1 · Быстрый расчёт

**Как гость, я хочу узнать ориентировочную стоимость ремонта, не регистрируясь и не разговаривая с менеджером.**

Форма, максимум 6 полей:

| Поле | Тип | Обязательное |
|---|---|---|
| Площадь, м² | число, 10–1000 | да |
| Тип объекта | квартира / частный дом | да |
| Объём работ | под ключ / чистовая / черновая | да |
| Пакет отделки | стандартный / дизайнерский | да |
| Состояние | новостройка / вторичка с демонтажом | да |
| Высота потолков | до 3 м / от 3 м | да |

**Критерии приёмки**

- [ ] Форма доступна с лендинга без регистрации
- [ ] При пакете «стандартный» результат появляется мгновенно, без обращения к серверу за ценой
- [ ] Результат — диапазон «от — до» в AMD с разделителями разрядов, а не одно число
- [ ] Рядом с ценой перечислено, что входит в стандартный пакет
- [ ] Показана дата действия расчёта (30 дней) и оговорка: «Предварительная оценка. Точная стоимость — после замера»
- [ ] При пакете «дизайнерский» цена **не показывается**; выводится: «Проект требует индивидуального расчёта — смета в течение 2 рабочих дней» и кнопка перехода к заявке
- [ ] Площадь вне диапазона 10–1000 м² → понятная ошибка, расчёт не выполняется
- [ ] Расчёт сохраняется в БД анонимно (для аналитики) и привязывается к пользователю при последующей регистрации
- [ ] Время от открытия страницы до результата — не более 60 секунд

### US-2 · Регистрация и верификация

**Как клиент, я хочу зарегистрироваться, чтобы отправить проект на расчёт.**

Поля: ФИО, e-mail, телефон (+374, маска), адрес объекта, пароль.

**Критерии приёмки**

- [ ] Все поля обязательны; телефон валидируется по формату Армении
- [ ] Пароль не короче 8 символов, содержит букву и цифру
- [ ] Повторный e-mail → ошибка «Пользователь с таким e-mail уже зарегистрирован» со ссылкой на вход
- [ ] После регистрации отправляется письмо со ссылкой верификации, срок жизни 24 часа
- [ ] До верификации пользователь входит в кабинет, но **не может отправить заявку**; вместо кнопки — баннер «Подтвердите e-mail»
- [ ] Кнопка «Отправить письмо повторно», не чаще одного раза в 60 секунд
- [ ] Повторный переход по использованной ссылке → «Ссылка уже использована», редирект на вход
- [ ] Истёкшая ссылка → предложение запросить новую
- [ ] Пароли хранятся как bcrypt-хеш, cost ≥ 10

### US-3 · Загрузка проекта

**Как клиент, я хочу загрузить план БТИ и желаемый дизайн.**

**Критерии приёмки**

- [ ] Два раздела: «План БТИ» и «Желаемый дизайн»
- [ ] Форматы: PDF, JPG, PNG, DWG. До 10 файлов на заявку, до 25 МБ каждый
- [ ] Drag-and-drop и выбор через диалог
- [ ] Прогресс загрузки по каждому файлу, возможность удалить до отправки
- [ ] Неподдерживаемый формат → «Формат не поддерживается. Загрузите PDF, JPG, PNG или DWG»
- [ ] Превышение размера → «Файл больше 25 МБ. Сожмите или разбейте на части»
- [ ] Заявка создаётся **и без файлов** — они не блокируют отправку
- [ ] Файлы отдаются только по подписанным ссылкам со сроком жизни 15 минут
- [ ] Прямой доступ к файлу чужой заявки → 403

### US-4 · Отправка на ручное рассмотрение

**Как клиент, я хочу отправить заявку сметчику, чтобы получить точную смету.**

**Критерии приёмки**

- [ ] Кнопка доступна и после автоматического расчёта, и вместо него при дизайнерском пакете
- [ ] Заявка содержит: параметры расчёта, результат автооценки (если был), файлы, контакты и **адрес объекта** — поле заявки, предзаполненное контактным адресом из профиля
- [ ] После отправки — статус «Принято в работу» и обещанный срок ответа
- [ ] Клиент получает письмо-подтверждение с номером заявки
- [ ] Заявок у клиента может быть несколько одновременно; от случайного дубля защищает окно «не более трёх созданных заявок в час» с понятным сообщением
- [ ] Заявка появляется в очереди админки в течение 5 секунд

### US-5 · Работа сметчика

**Как сметчик, я хочу видеть очередь заявок и загружать в них сметы.**

**Критерии приёмки**

- [ ] Список заявок с фильтром по статусу и сортировкой по дате
- [ ] Карточка заявки открывает все параметры, контакты и файлы с одного экрана
- [ ] Загрузка PDF-сметы и указание итоговой суммы в AMD
- [ ] Статусы: `новая` → `в работе` → `нужны данные` → `смета готова` → `принята` / `отклонена`
- [ ] Статус «нужны данные» отправляет клиенту письмо с комментарием сметчика
- [ ] При переводе в «смета готова» клиент автоматически уведомляется
- [ ] Все смены статуса пишутся в журнал: кто, когда, из какого в какой

### US-6 · Решение клиента

**Как клиент, я хочу принять или отклонить смету.**

**Критерии приёмки**

- [ ] Смета доступна для просмотра и скачивания в кабинете
- [ ] Кнопки «Принять» и «Отклонить»
- [ ] При отказе — обязательный выбор причины: дорого / долго / выбрал другого подрядчика / отложил ремонт / другое
- [ ] Вариант «другое» открывает поле для текста
- [ ] Причина сохраняется и видна в админке
- [ ] Решение необратимо; повторное нажатие невозможно
- [ ] При принятии менеджер получает уведомление в течение минуты

### US-7 · Управление ценами

**Как админ, я хочу менять базовую ставку и коэффициенты без релиза.**

**Критерии приёмки**

- [ ] Форма редактирования базовой ставки (по умолчанию 60 000 AMD) и всех коэффициентов
- [ ] Сохранение создаёт **новую версию** набора ставок, старая не удаляется
- [ ] Новые расчёты используют актуальную версию; ранее выданные оценки не пересчитываются
- [ ] Каждый расчёт хранит идентификатор версии ставок, по которой он сделан
- [ ] История изменений: кто, когда, что поменял

### US-8 · Локализация

**Критерии приёмки**

- [ ] Переключатель ru / hy / en в шапке
- [ ] Выбор сохраняется между сессиями
- [ ] Переведены интерфейс, письма и тексты ошибок
- [ ] Суммы форматируются как `4 800 000 ֏` во всех локалях
- [ ] Непереведённых строк в интерфейсе нет

### US-9 · Показать / скрыть пароль

**Как человек, вводящий пароль, я хочу увидеть то, что набрал, чтобы не входить
вслепую с третьей попытки.**

Поле пароля есть на трёх экранах: вход, регистрация и установка нового пароля.
Опечатка в скрытом поле стоит человеку целого цикла «ошибка — повтор», а на
экране регистрации — ещё и неизвестного ему самому пароля в базе.

**Критерии приёмки**

- [ ] У каждого поля пароля — переключатель внутри поля, справа от текста
- [ ] Нажатие показывает пароль, повторное нажатие скрывает
- [ ] Переключатель — настоящая кнопка `type="button"`: нажатие **не отправляет форму**
- [ ] Доступное имя меняется вместе с состоянием: «Показать пароль» / «Скрыть пароль»
- [ ] Состояние объявлено через `aria-pressed`
- [ ] Кнопка достигается с клавиатуры, фокус виден
- [ ] Иконка — глаз и перечёркнутый глаз, рисуется инлайновым SVG в фирменном стиле
- [ ] Автозаполнение браузера и менеджеры паролей продолжают работать: переключается
      атрибут `type` у того же поля, поле не пересоздаётся, `autocomplete` сохраняется
- [ ] Состояние у каждого поля своё и сбрасывается при переходе на другую страницу:
      показанный пароль не «утекает» на следующий экран
- [ ] Подписи переведены на ru / hy / en

### US-10 · Восстановление пароля

**Как клиент, забывший пароль, я хочу войти в кабинет, а не регистрироваться
заново на второй e-mail.**

Заявки, файлы и сметы привязаны к аккаунту. Без восстановления человек с
забытым паролем теряет не доступ, а всю переписку по своему ремонту — и
звонит в компанию, то есть тратит те самые часы, ради экономии которых
существует платформа.

**Критерии приёмки**

- [ ] На странице входа — ссылка «Забыли пароль?»
- [ ] Страница запроса: одно поле e-mail и кнопка «Отправить ссылку»
- [ ] Ответ **одинаков** для существующего и несуществующего адреса: экран
      «письмо отправлено», тот же код ответа, то же тело. Существование аккаунта
      по этому эндпоинту не определяется
- [ ] Письмо приходит на языке профиля и содержит ссылку `/reset?token=…`
- [ ] Ссылка действует **60 минут** и срабатывает один раз
- [ ] Страница `/reset` просит новый пароль дважды; правила те же, что при
      регистрации (≥8 символов, минимум одна буква и одна цифра)
- [ ] Несовпадение полей — ошибка до отправки на сервер
- [ ] Истёкшая ссылка → «Срок действия ссылки истёк» и предложение запросить новую
- [ ] Использованная ссылка → «Ссылка уже использована»
- [ ] Недействительная ссылка → «Ссылка недействительна»
- [ ] После смены пароля **все сессии гасятся**: открытые в других браузерах
      входы перестают работать, войти можно только новым паролем
- [ ] Прочие неиспользованные ссылки восстановления того же человека перестают
      работать
- [ ] Старый пароль после смены не подходит
- [ ] Частота запросов ограничена, как у остальных эндпоинтов входа
- [ ] В базе лежит только SHA-256 от токена; в логи и в тексты ошибок токен не попадает
- [ ] Интерфейс и письмо переведены на ru / hy / en

## 6. Контракты API

```
POST   /auth/register              → создать пользователя, отправить письмо
POST   /auth/verify                → подтвердить e-mail по токену
POST   /auth/resend-verification
POST   /auth/forgot-password       → письмо со ссылкой восстановления (ответ не зависит от наличия аккаунта)
POST   /auth/reset-password        → новый пароль по токену, все сессии гасятся
POST   /auth/login                 → access + refresh
POST   /auth/refresh

POST   /pricing/estimate           → расчёт вилки (публичный)
GET    /pricing/rates              → актуальные ставки (публичный)
PUT    /admin/pricing/rates        → новая версия ставок

POST   /requests                   → создать заявку
GET    /requests/me                → заявки текущего пользователя
GET    /requests/:id
POST   /requests/:id/decision      → принять / отклонить

POST   /files/upload-url           → подписанная ссылка на загрузку
GET    /files/:id/download-url     → подписанная ссылка на скачивание

GET    /admin/requests             → очередь с фильтрами
PATCH  /admin/requests/:id/status
POST   /admin/requests/:id/quote   → загрузить смету
```

## 7. Edge cases

| Ситуация | Поведение |
|---|---|
| Клиент занизил площадь | В смете фиксируется: пересчёт при расхождении более 5% после замера |
| План БТИ без масштаба | Статус «нужны данные» с комментарием; заявка не отклоняется |
| Объект вне зоны работ | Проверка региона на первом шаге калькулятора, до расчёта |
| Возврат со старым расчётом | Срок действия 30 дней, далее пересчёт по актуальной версии ставок |
| Дубли заявок | Дедупликация по телефону, склейка в одну карточку в админке |
| Файл больше лимита | Понятная ошибка с инструкцией, не «upload failed» |
| Одновременная загрузка 10 файлов | Параллельная загрузка, независимый прогресс, частичный сбой не роняет заявку |
| Админ поменял ставки во время расчёта | Расчёт завершается по версии, зафиксированной на старте |
| Клиент удалил письмо верификации | Повторная отправка не чаще раза в 60 секунд |
| Клиент забыл пароль | Ссылка восстановления на 60 минут; после смены пароля все сессии гасятся |
| Перебор адресов через «забыли пароль» | Ответ одинаков для любого адреса, частота запросов ограничена |
| Ссылка восстановления попала в чужие руки | Один проход, 60 минут, прочие ссылки того же человека гасятся при использовании любой из них |
| Сметчик загрузил смету не в ту заявку | Замена файла с записью в журнал |

## 8. Метрики

**Главная:** часы выезда и работы сметчика на одну закрытую сделку.

**Диагностические:** конверсия лендинг → расчёт; расчёт → регистрация; регистрация → верификация; заявка → смета; смета → принятие; распределение причин отказа; доля дизайнерских пакетов; доля заявок с файлами; время от заявки до сметы; отклонение автооценки от финальной сметы.
