# RenovateAM — чат-бот на сайте

Версия 0.1 · 21.10.2026 · статус: контракт под реализацию

Документ — единственный источник истины для модуля `chat`. Команды бэкенда и фронтенда
работают параллельно, поэтому всё, что пересекает границу между ними, зафиксировано здесь.
Что не описано — не додумывается, а выносится в «Открытые вопросы» в конце.

---

## 1. Что это и зачем

Виджет в правом нижнем углу всех публичных страниц. Посетитель задаёт вопрос обычными
словами и получает ответ из базы знаний — без регистрации. После первого ответа бот просит
имя, почту и телефон: дальше разговор продолжается только с контактами. Каждый такой
разговор — лид: он попадает в админку и уведомлением менеджеру.

**Чего бот НЕ делает в первой фазе.** Не считает цену внутри диалога (кнопка ведёт на
калькулятор), не создаёт заявку, не обращается к языковой модели. Ответы детерминированы:
на один и тот же вопрос бот всегда отвечает одинаково. Это сознательный выбор — бот
говорит от лица компании о деньгах и сроках, и выдумывать он не должен.

## 2. Язык

Три языка: `ru`, `hy`, `en` (значения существующего enum `Locale`).

**Определение языка сообщения** (`detectLocale(text, fallback)`):

1. Есть символы кириллицы (U+0400–U+04FF) → `ru`.
2. Есть символы армянского блока (U+0530–U+058F) → `hy`.
3. Только латиница → решает индекс ключевых слов: считаем совпадения нормализованного
   текста с латинскими ключами армянских формулировок и с английскими. Больше совпадений
   у армянской латиницы → `hy`, иначе → `en`. Ноль совпадений у обеих → `fallback`.
4. `fallback` — язык интерфейса сайта, с которым виджет открыли.

Армянская латиница — это армянский язык, записанный латиницей («barev, inch arji qarakusi
metry»). Отвечаем на него **армянским письмом**: человек, который так пишет, армянский
читает свободно, а латиница в ответе выглядит как неуважение к языку.

Язык определяется для каждого сообщения заново и сохраняется в сессии (`ChatSession.locale`)
как язык последнего сообщения: ответ, приветствие и письма менеджеру идут на нём.

## 3. База знаний

### 3.1 Формат

Файл `apps/api/src/modules/chat/knowledge/entries.ts` — данные, не логика. Тип лежит
рядом в `types.ts`:

```ts
export type ChatActionKind =
  | 'ESTIMATE'   // кнопка «Посчитать цену» → /#calculator
  | 'REQUEST'    // «Оставить заявку» → /request
  | 'PORTFOLIO'  // «Посмотреть работы» → Instagram
  | 'CALL'       // «Позвонить» → tel:
  | 'HUMAN';     // «Позвать человека» → handoff

export interface ChatEntry {
  id: string;                 // стабильный id темы, уходит в аналитику
  topic: string;              // название темы по-русски, для админки и логов
  label: Localized;           // короткая подпись для кнопок уточнения, до 32 символов
  keywords: ChatKeywords;     // ru / hy / hyLatin / en
  answer: Localized;          // ru / hy / en, пустых значений быть не должно
  actions?: ChatActionKind[]; // максимум две кнопки
}
```

Точные определения — в `apps/api/src/modules/chat/knowledge/types.ts`; он уже в репозитории
и является общим словарём обеих команд. Файл `entries.ts` редактирует только команда базы
знаний, движок и API его не трогают.

Служебные ответы (приветствие, запрос контактов, «не понял», прощание) лежат в том же
файле отдельной константой `SERVICE_ENTRIES` с фиксированными id: `greeting`,
`contacts_request`, `contacts_thanks`, `fallback`, `handoff_done`.

### 3.2 Поиск

Детерминированный поиск по ключевым словам, без эмбеддингов и без сети.

1. **Нормализация** запроса и ключей: нижний регистр, `ё`→`е`, убрать пунктуацию и
   диакритику, схлопнуть пробелы. Для армянского письма дополнительно строится латинская
   транслитерация по таблице (`ա`→`a`, `բ`→`b`, … `ու`→`u`, `և`→`ev`), чтобы «քարակուսի»
   и «qarakusi» попадали в один ключ.
2. **Счёт.** Для каждой темы: сумма весов совпавших ключей, вес = число слов в ключе
   (ключ из двух слов ценнее односложного) + 0.5 за совпадение целой фразой. Результат
   делится на длину запроса в словах, чтобы длинный вопрос не выигрывал автоматически.
3. **Порог.** Лучший счёт меньше `MIN_SCORE` → ответ `fallback` с кнопкой `HUMAN`.
4. **Спорный случай.** Второй результат отстаёт меньше чем на 15 % → бот не угадывает, а
   переспрашивает: «Уточните, пожалуйста: про А или про Б?» с двумя вариантами в
   `suggestions`. Это отдельный тип ответа, не `fallback`.

Движок — чистая функция без зависимостей от Nest и Prisma: на вход запрос и база, на
выходе решение. Так он тестируется таблицей «фраза → ожидаемая тема» (§7).

## 4. Данные

Новые таблицы, владелец — модуль `chat`. Правило `@owner` в `schema.prisma` обязательно,
иначе упадёт `scripts/check-module-boundaries.mjs`.

```prisma
enum ChatRole { VISITOR BOT }

/// @owner: chat — разговор посетителя с ботом. Существует без регистрации.
model ChatSession {
  id                 String    @id @default(uuid()) @db.Uuid
  /// Язык последнего сообщения посетителя.
  locale             Locale
  /// Заполняется, если посетитель вошёл в кабинет. Для анонима null.
  userId             String?   @map("user_id") @db.Uuid
  contactName        String?   @map("contact_name") @db.VarChar(120)
  contactEmail       String?   @map("contact_email") @db.VarChar(254)
  contactPhone       String?   @map("contact_phone") @db.VarChar(32)
  /// Момент, когда контакты заполнены. До этого сессия лидом не считается.
  leadCapturedAt     DateTime? @map("lead_captured_at") @db.Timestamptz(3)
  /// Посетитель попросил живого человека.
  handoffRequestedAt DateTime? @map("handoff_requested_at") @db.Timestamptz(3)
  /// Менеджер отметил лид обработанным.
  handledAt          DateTime? @map("handled_at") @db.Timestamptz(3)
  handledById        String?   @map("handled_by_id") @db.Uuid
  /// Страница, с которой начат разговор. Нужна, чтобы понимать контекст вопроса.
  pageUrl            String?   @map("page_url") @db.VarChar(500)
  lastMessageAt      DateTime  @default(now()) @map("last_message_at") @db.Timestamptz(3)
  createdAt          DateTime  @default(now()) @map("created_at") @db.Timestamptz(3)

  messages ChatMessage[]

  @@index([leadCapturedAt])
  @@index([handledAt, lastMessageAt])
  @@map("chat_sessions")
}

/// @owner: chat — одно сообщение в разговоре.
model ChatMessage {
  id        String   @id @default(uuid()) @db.Uuid
  sessionId String   @map("session_id") @db.Uuid
  role      ChatRole
  text      String   @db.VarChar(2000)
  /// id темы из базы знаний, по которой отвечал бот. Для сообщений посетителя null.
  entryId   String?  @map("entry_id") @db.VarChar(64)
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)

  session ChatSession @relation(fields: [sessionId], references: [id], onDelete: Cascade)

  @@index([sessionId, createdAt])
  @@map("chat_messages")
}
```

Отдельной таблицы лидов нет: лид — это сессия с заполненными контактами. Один источник
истины, никакой рассинхронизации между «разговором» и «заявкой на звонок».

Миграция — `apps/api/prisma/migrations/0005_chat/migration.sql`, обычный SQL, как все
предыдущие. Prisma CLI в этой среде заблокирована прокси, генерация клиента — через
`pnpm --filter @renovateam/api db:setup`.

## 5. API

Все эндпоинты диалога публичные (`@Public()`), админские — под ролью сотрудника.
Конверт ошибок прежний: `{ error: { code, message, details?, requestId } }`.

### 5.1 Диалог

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/chat/sessions` | `{ locale, pageUrl? }` | `201 { sessionId, locale, reply }` |
| POST | `/chat/sessions/:id/messages` | `{ text }` | `200 { reply }` |
| POST | `/chat/sessions/:id/contacts` | `{ name, email, phone }` | `200 { reply }` |
| POST | `/chat/sessions/:id/handoff` | — | `200 { reply }` |

`reply` одинаков везде:

```ts
interface ChatReply {
  text: string;                 // уже на языке сессии
  entryId: string;              // тема или служебный id
  actions: ChatActionKind[];    // максимум две кнопки
  suggestions: string[];        // готовые реплики-подсказки, максимум три
  needsContacts: boolean;       // true → виджет показывает форму контактов
}
```

**Правила.**

- `needsContacts` становится `true` в ответе на **первое** сообщение посетителя, если
  контакты ещё не заполнены. Пока их нет, `POST /messages` отвечает `403`
  `CHAT_CONTACTS_REQUIRED` — приветствие и первый вопрос бесплатны, дальше нужны контакты.
- `text` длиной 1–1000 символов после `trim`. Пусто или больше — `400` `VALIDATION_FAILED`.
- Не больше 60 сообщений посетителя на сессию → `429` `CHAT_SESSION_EXHAUSTED`.
- Неизвестный `sessionId` → `404` `CHAT_SESSION_NOT_FOUND`. Сессия старше 24 часов
  считается закрытой: тот же `404`, виджет молча начинает новую.
- Троттлинг: отдельная группа `chat`, 20 сообщений в минуту на IP.
- `handoff` идемпотентен: повторный вызов не плодит уведомления.

**Контакты.** `name` 2–120 символов; `email` — валидный адрес; `phone` нормализуется к
`+374XXXXXXXX` (принимаем `099…`, `+374 99 …`, `00374…`, пробелы и дефисы), невалидный —
`400` с полем в `details`. Ответ — `contacts_thanks` и, если посетитель ждал ответа на
вопрос, сразу ответ на него.

### 5.2 Админка

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/admin/chat/sessions?handled=&page=&perPage=` | Список лидов, новые сверху |
| GET | `/admin/chat/sessions/:id` | Разговор целиком |
| POST | `/admin/chat/sessions/:id/handled` | Отметить обработанным |

В список попадают только сессии с контактами **или** с запросом человека: разговоры
анонимов, ушедших после первого вопроса, менеджеру не нужны. В строке — имя, телефон,
почта, время, первый вопрос, флаг «просил человека», флаг «обработан».

## 6. Уведомления

Два новых события в публичном контракте `notifications`:

```ts
| { type: 'CHAT_LEAD'; to: string; locale: Locale;
    name: string; phone: string; email: string; question: string; adminLink: string }
| { type: 'CHAT_HANDOFF'; to: string; locale: Locale;
    name: string; phone: string; question: string; adminLink: string }
```

`to` — `MANAGER_EMAIL` из конфигурации.

**Канал Telegram** — новый файл `channels/telegram.channel.ts`, поддерживает только эти
два события. Конфигурация: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Обе переменные
пустые → канал не регистрируется, и это нормальный режим (так работает локальная
разработка), но в `NODE_ENV=production` отсутствие токена пишется в лог один раз при
старте — молча терять уведомления нельзя.

Сообщение короткое и со ссылкой, переписка целиком в Telegram не уходит:

```
🔔 Новый лид из чата
Ани · +374 99 099 457
Спрашивала: сколько стоит ремонт 60 м² под ключ
→ https://renovateam.am/admin/chat/<id>
```

Отправка — `POST https://api.telegram.org/bot<TOKEN>/sendMessage`, тело
`{ chat_id, text, disable_web_page_preview: true }`, таймаут 5 секунд. Ошибка канала не
роняет операцию (правило модуля: `accepted: false`, лид уже сохранён).

## 7. Фронтенд

### 7.1 Жёсткие требования заказчика

Это критерии приёмки, а не пожелания:

1. **Иконка не двигается при скролле.** `position: fixed`, правый нижний угол. На
   мобильном учитываются safe-area-инсеты.
2. **Появление и исчезновение — плавные.** Открытие ~220 мс, закрытие ~180 мс,
   прозрачность + лёгкий подъём и масштаб. При `prefers-reduced-motion` остаётся только
   прозрачность.
3. **Закрытие только по кнопке ×.** Клик вне панели НЕ закрывает чат. Клавиша Escape
   закрывает — это стандарт доступности и не противоречит требованию.
4. **Анимированный маскот** в приветствии: современный, в фирменных цветах, не «кустарный».
   Реализация — инлайновый SVG + CSS, без Lottie и без сторонних зависимостей.
5. **Телефон.** Ниже 640 px панель разворачивается на весь экран (`100dvh`), поле ввода
   не перекрывается клавиатурой, попадания пальцем — не меньше 44 px.

### 7.2 Маскот

Собственный персонаж в палитре бренда, не копия чужого:

- корпус — светлый `#EDF1EE` с мягкой тенью, визор — тёмный изумруд `#0E2B25`;
- глаза — две дуги шампанского цвета `#C9B183` со свечением; форма дуги повторяет арку
  из знака компании, это связывает маскота с логотипом;
- «антенна» с замковым камнем на конце — та же деталь, что в знаке;
- анимации: парение (3 с, туда-обратно), моргание (раз в 4–6 с, случайная задержка),
  лёгкий наклон при появлении; всё выключается при `prefers-reduced-motion`;
- размер в приветствии 96 px, в шапке панели — 32 px, статичный.

Запрещено: растровые картинки, внешние анимации, шрифтовые иконки, эмодзи вместо лица.

### 7.3 Поведение

- Виджет на всех публичных страницах; в кабинете и админке его нет.
- Язык интерфейса виджета = язык сайта. Ответы приходят с сервера уже переведёнными.
- История разговора хранится в памяти вкладки; `sessionId` — в `sessionStorage`, чтобы
  переход между страницами не обрывал разговор. Пусто или `404` от сервера → новая сессия.
- Форма контактов появляется после первого ответа бота, внутри ленты сообщений, а не
  модальным окном. Поля: имя, телефон, почта. Ошибки валидации — под полями, по-человечески.
- Кнопки действий (`actions`) рисуются подписями из i18n по `kind`, ссылки — внутренние
  маршруты приложения; Instagram открывается в новой вкладке с `rel="noopener"`.
- Индикатор «бот печатает» — 400–700 мс перед ответом. Это честно: ответ действительно
  готовится, а мгновенная выдача выглядит как подстановка и пугает.
- Ключи i18n — пространство `chat.*` в `ru.json`, `hy.json`, `en.json`. Ни одной строки
  в коде компонентов.

### 7.4 Админка

Страница `/admin/chat` — список лидов, и `/admin/chat/:id` — разговор целиком с кнопкой
«Обработан». Вёрстка и состояния — как в существующих админских списках, без новых
паттернов.

## 8. Тесты (обязательный минимум)

- **Движок поиска**: таблица «фраза → ожидаемая тема» не меньше 30 строк, во всех четырёх
  раскладках, включая армянскую латиницу, опечатки и короткие реплики («цена?», «inch arji»).
- **Порог и спорный случай**: бессмысленный запрос даёт `fallback`; два близких
  результата дают переспрос, а не угадывание.
- **Определение языка**: по два примера на каждое правило §2.
- **Контакты обязательны**: второе сообщение без контактов — `403`; после `POST /contacts`
  проходит.
- **Нормализация телефона**: `099099457`, `+374 99 099 457`, `00374 99-09-94-57` → один и
  тот же `+37499099457`; `12345` → `400`.
- **Лид уходит в уведомления**: событие `CHAT_LEAD` отправлено ровно один раз, после
  коммита; падение канала не ломает ответ API.
- **Админка**: анонимная сессия без контактов в списке лидов не появляется.
- **Виджет**: тест, что клик по оверлею не закрывает панель, а клик по × закрывает.

Гейты прежние и должны быть зелёными: `pnpm lint`, `pnpm typecheck`, `pnpm test`.

## 9. Открытые вопросы

1. **Хранение переписки.** Сейчас храним тексты сообщений бессрочно. Нужен срок жизни —
   предложение: чистить сессии без контактов через 30 дней, с контактами — хранить.
2. **Расчёт цены в диалоге** (фаза 2): бот спрашивает площадь и пакет и считает вилку
   через `pricing-core` прямо в чате. Контракт появится отдельным разделом.
3. **Редактирование базы знаний без разработчика.** Пока база — файл в репозитории.
   Если тем станет заметно больше, переносим в таблицу и даём экран в админке.
